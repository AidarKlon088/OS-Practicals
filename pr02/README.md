# PR2 — Bash и системные вызовы (вариант A)

## Цель

Написать Bash-скрипт для обработки набора журналов (подсчёт ошибок `ERROR`) и изучить
системные вызовы программ Linux с помощью `strace`.

## Файлы

| Файл | Назначение |
|---|---|
| `generate_logs.py` | создаёт 50 журналов `data/01.log … data/50.log` по 20 строк |
| `data/*.log` | журналы: `дата время УРОВЕНЬ module=system msg=event_N` |
| `stats.sh` | считает `ERROR` в каждом файле, общее число и файл с максимумом |
| `stats_output.txt` | реальный вывод `stats.sh` |
| `strace_ls.txt`, `strace_cat.txt` | сводка системных вызовов (`strace -c`) |
| `strace_openat.txt` | все вызовы `openat` программы `cat` |

## Запуск (Ubuntu WSL2)

```bash
cd /mnt/c/Users/user/Desktop/OS-Practicals/pr02
python3 generate_logs.py                           # создать data/*.log
bash stats.sh | tee stats_output.txt
strace -c -o strace_ls.txt ls data > /dev/null
strace -c -o strace_cat.txt cat data/01.log > /dev/null
strace -e trace=openat -o strace_openat.txt cat data/01.log > /dev/null
```

## Объяснение скрипта stats.sh

* `for f in data/*.log` перебирает журналы; `[ -f "$f" ] || continue` пропускает
  несуществующий шаблон, если файлов нет.
* `grep -c "ERROR" "$f"` считает строки с `ERROR`. При 0 совпадений `grep` возвращает
  код 1, поэтому добавлено `|| true`.
* `total=$((total + count))` — арифметика Bash; `(( count > max_errors ))` — сравнение
  чисел.
* Сравнение строгое (`>`), поэтому при равенстве остаётся **первый** найденный файл.

## Результаты выполнения

```text
data/01.log: 6 ошибок
...
-----------------------------
Всего ошибок: 230
Больше всего ошибок: data/07.log
Количество ошибок: 10
```

**Количество журналов:** 50

**Всего ошибок ERROR:** 230

**Файл с наибольшим количеством ошибок:** `data/07.log`

**Максимальное количество ошибок в одном файле:** 10

**Ручная проверка.** В `generate_logs.py` строка `j` файла `i` — это `ERROR`, если
`j % (i % 7 + 2) == 0`. Значит, в файле ⌊20 / (i mod 7 + 2)⌋ ошибок:

| `i mod 7` | делитель | ошибок в файле | файлов | всего |
|---|---|---|---|---|
| 0 | 2 | 10 | 7 (07, 14, …, 49) | 70 |
| 1 | 3 | 6 | 8 (01, 08, …, 50) | 48 |
| 2 | 4 | 5 | 7 | 35 |
| 3 | 5 | 4 | 7 | 28 |
| 4 | 6 | 3 | 7 | 21 |
| 5 | 7 | 2 | 7 | 14 |
| 6 | 8 | 2 | 7 | 14 |
| | | | **50** | **230** |

Итог совпадает с выводом скрипта (и с `cat data/*.log | grep -c ERROR` → 230).
Максимум 10 ошибок есть сразу в **7 файлах**: 07, 14, 21, 28, 35, 42, 49. Скрипт
выводит первый из них, `data/07.log`.

### Анализ системных вызовов

Команда `strace -c` показала системные вызовы программ `ls` и `cat`
(всего 145 и 142 вызова). Три наиболее частых по числу вызовов — одинаковые у обеих
программ:

| Вызов | `ls` | `cat` | Назначение |
|---|---|---|---|
| `mmap` | 27 | 27 | отображение файлов (библиотек) и выделение памяти в адресном пространстве процесса |
| `read` | 18 | 18 | чтение данных из файлового дескриптора (заголовки библиотек, файлы `/proc`, журнал) |
| `openat` | 12 | 12 | открытие файла и получение дескриптора |

Сразу за ними идут `close` (11 и 13) и `fstat`. Специфичные вызовы: у `ls` —
`getdents64` (чтение записей каталога), у `cat` — `splice` (копирование данных из файла
в вывод внутри ядра, без копирования в память программы).

Ранжирование по **числу** вызовов, а не по проценту времени: время отдельных вызовов
измеряется в микросекундах и меняется от запуска к запуску, а их количество стабильно.

`strace_openat.txt` показывает 12 вызовов `openat` у `cat` (один файл локализации
не найден — `ENOENT`), и только последний открывает `data/01.log`. До этого загружаются кэш динамического компоновщика (`/etc/ld.so.cache`)
и разделяемые библиотеки (`libc.so.6`, `libm.so.6`, `libgcc_s.so.1`, `libselinux.so.1`,
`libpcre2-8.so.0`), читаются `/proc/self/maps`, `/proc/mounts` и файлы локализации.
Библиотеки нужны для запуска самой программы, а не для чтения журнала. В Ubuntu 26.04
`cat` — это реализация coreutils на Rust (`uucore`), поэтому список отличается от
классического GNU `cat`.

### Вывод

Я создал Bash-скрипт для подсчёта ошибок в 50 журналах, определил файл с наибольшим
количеством ошибок (при равенстве — первый из семи) и проверил результат ручным расчётом.
С помощью `strace` я увидел, что даже простая команда выполняет более 140 системных
вызовов, и большая часть из них нужна для загрузки программы, а не для её основной работы.
