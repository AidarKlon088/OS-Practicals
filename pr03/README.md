# PR3 — Процессы в Linux (вариант A)

## Цель

Изучить жизненный цикл процессов Linux: найти PID и PPID, посмотреть состояние и память
процесса через `ps` и `/proc`, создать дочерний процесс с помощью `fork()`, дождаться
его завершения и получить зомби-процесс.

## Файлы

| Файл | Назначение |
|---|---|
| `fork_demo.py` | `os.fork()` + `os.wait()`: родитель ждёт ребёнка и получает код возврата |
| `zombie.py` | ребёнок сразу завершается, родитель 30 с не вызывает `waitpid()` → зомби |
| `run_all.sh` | исследует процесс `sleep`, запускает обе программы и сохраняет вывод в `results_*.txt` |
| `results_sleep.txt`, `results_fork.txt`, `results_zombie.txt` | реальный вывод |

## Запуск (Ubuntu WSL2)

```bash
cd /mnt/c/Users/user/Desktop/OS-Practicals/pr03

# процесс sleep
sleep 100 &
ps -o pid,ppid,stat,cmd -p $!
grep -E 'State|VmRSS|Threads' /proc/$!/status
kill $!

python3 fork_demo.py

# зомби: во втором терминале в течение 30 с
python3 zombie.py
ps -o pid,ppid,stat,cmd --ppid <PID родителя>

bash run_all.sh        # всё сразу (~30 с) -> results_*.txt
```

## Результаты выполнения

### Процесс sleep (`results_sleep.txt`)

```text
$ ps -o pid,ppid,stat,cmd -p 445
    PID    PPID STAT CMD
    445     349 S+   sleep 100
$ grep -E 'State|VmRSS|Threads' /proc/445/status
State:	S (sleeping)
VmRSS:	    7736 kB
Threads:	1
$ kill 445
код завершения: 143 (128 + 15 = SIGTERM)
```

* **Состояние:** `S` (sleeping) — процесс ждёт истечения таймера и не занимает CPU;
  `+` — процесс в группе переднего плана терминала.
* **Память (VmRSS):** около 7.7 МБ физической памяти. При разных запусках значение
  немного отличается (в первом запуске было 7840 kB).
* **Потоков:** 1.
* **Завершение:** `kill` по умолчанию посылает `SIGTERM` (15). Код завершения
  `143 = 128 + 15` показывает, что процесс завершён сигналом.

### fork_demo.py (`results_fork.txt`)

Я создал дочерний процесс с помощью `os.fork()`. Родительский процесс вызвал `os.wait()`,
чтобы дождаться завершения ребёнка и получить код возврата.

```text
Я ребёнок, PID=450, PPID=449
Я родитель, PID=449
Ребёнок 450 завершился с кодом 0
```

* `fork()` возвращает **0** в ребёнке и **PID ребёнка** в родителе. По этому значению
  программа определяет, в каком процессе она выполняется.
* PPID ребёнка (449) совпадает с PID родителя.
* Порядок строк «ребёнок / родитель» не гарантирован — его определяет планировщик.

### zombie.py (`results_zombie.txt`)

Зомби — это завершённый процесс, статус которого ещё не забрал родитель (`wait`/`waitpid`).

```text
Родитель PID=451
Дочерний PID=453
$ ps -o pid,ppid,stat,cmd -p 451,453
    PID    PPID STAT CMD
    451     349 S+   python3 zombie.py
    453     451 Z+   [python3] <defunct>
Зомби-процесс исчез после waitpid()
$ ps -o pid,stat -p 453      # после waitpid()
    PID STAT
(процесс 453 больше не существует)
```

* Ребёнок 453 в состоянии **`Z`** и помечен `<defunct>`. Он уже не выполняется и не
  занимает память, но запись в таблице процессов (PID и код возврата) остаётся,
  пока её не заберёт родитель.
* После `os.waitpid()` запись удаляется, и процесс 453 исчезает из `ps`.

## Вывод

Я изучил жизненный цикл процессов Linux: научился находить PID и PPID, смотреть
состояние, память и число потоков через `ps` и `/proc/PID/status`, создавать дочерние
процессы через `fork()` и забирать их код возврата через `wait()`. Если родитель не
вызывает `wait()`, завершённый ребёнок остаётся зомби (`Z`). Если таких процессов
много, они занимают PID, поэтому родитель обязан забирать статус потомков.

## Ответы на контрольные вопросы

> Вопросы методички недоступны; ниже — ответы на типовые вопросы по теме.

1. **Что такое PID и PPID?** PID — уникальный номер процесса, PPID — PID его родителя.
2. **Какие состояния процесса показывает `ps`?** `R` — выполняется или готов,
   `S` — прерываемое ожидание, `D` — непрерываемое ожидание (обычно ввод-вывод),
   `T` — остановлен, `Z` — зомби.
3. **Что возвращает `fork()`?** 0 в потомке, PID потомка в родителе, −1 (исключение
   в Python) при ошибке.
4. **Что такое зомби-процесс и как его убрать?** Завершённый процесс, код возврата
   которого не забрал родитель. Убрать: родитель вызывает `wait()`/`waitpid()`. Если
   завершить родителя, зомби «усыновит» `init` (PID 1), который сам заберёт статус.
5. **Чем зомби отличается от сироты?** Сирота — работающий процесс, родитель
   которого завершился; его PPID становится 1 (или PID процесса-«сборщика»).
