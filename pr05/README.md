## Цель

и Round Robin, построить диаграмму Ганта и посчитать среднее время ожидания и оборота.

## Формат входных данных

```text
# PID arrival burst priority
P1 0 5 3
P2 1 3 1
```

Строки с `#` и пустые строки игнорируются. `priority` читается, но в варианте A
(FCFS/SJF/RR) не используется.

## Соглашения (разрешение равенств)

| Алгоритм | Правило |
|---|---|
| FCFS | по `arrival`; при равенстве — порядок строк в файле |
| SJF | среди пришедших — минимальный `burst`; при равенстве — меньший `arrival`, затем порядок в файле; процесс работает до конца (невытесняющий) |
| RR | очередь FIFO; процессы, пришедшие к моменту окончания кванта (включительно), ставятся в очередь **раньше** вытесненного процесса |
| все | если готовых процессов нет — CPU простаивает (`idle` в диаграмме) |

Формулы: `TAT = completion − arrival`, `WT = TAT − burst`.

## Объяснение кода

* `read_processes()` разбирает файл и проверяет число полей и корректность значений.
* `fcfs()` сортирует процессы по приходу и выполняет их по очереди, добавляя
  `idle`, если следующий процесс ещё не пришёл.
* `sjf()` в каждый момент выбирает среди пришедших процесс с минимальным `burst`.
* `rr()` хранит очередь `deque`; функция `admit()` переносит в очередь пришедшие
  процессы. После каждого кванта сначала вызывается `admit()`, а затем вытесненный
  процесс возвращается в конец очереди — так реализовано правило порядка RR.
* `gantt_text()` рисует диаграмму, ширина ячейки пропорциональна длительности.
* `metrics()` считает `TAT`, `WT` и средние значения.

## Проверка на set1 (ручной расчёт)

`set1`: P1(0,5), P2(1,3), P3(2,8), P4(3,6).

* **FCFS:** P1 0–5, P2 5–8, P3 8–16, P4 16–22. WT = 0, 4, 6, 13 → **5.75**; TAT = 5, 7, 14, 19 → **11.25**.
* **SJF:** в t=0 есть только P1 (0–5); в t=5 готовы P2(3), P4(6), P3(8) → P2 5–8, P4 8–14, P3 14–22.
  WT = 0, 4, 12, 5 → **5.25**; TAT → **10.75**.
* **RR, q=3:** P1 0–3; к t=3 пришли P2, P3, P4 и встали перед P1 → очередь P2,P3,P4,P1.
  P2 3–6 (готов), P3 6–9, P4 9–12, P1 12–14 (готов), P3 14–17, P4 17–20 (готов), P3 20–22.
  WT = 9, 2, 12, 11 → **8.50**; TAT = 14, 5, 20, 17 → **14.00**.

Программа дала ровно эти значения. Расхождений с ручным расчётом нет.
`test_sched.py` также проверяет `set2` по учебнику (FCFS WT=17, SJF WT=3,
RR q=4 WT=5.67) и граничные случаи (правило очереди RR, равный burst в SJF, простой CPU).
Результат: **15 проверок, все пройдены** (`test_results.txt`).

## Какой алгоритм эффективнее для set3 и почему

На `set3` лучший результат дал **RR (q=3)**: среднее ожидание 4.17 против 6.17 (SJF)
и 6.33 (FCFS).

Причина: длинный процесс P1 (burst = 10) приходит **один** в момент 0. Невытесняющий
SJF в этот момент выбирать не из чего, поэтому P1 занимает CPU до t=10, а короткие
P2, P3, P4 ждут по 8–10 единиц — это тот же эффект конвоя, что у FCFS. SJF лишь
немного меняет порядок коротких процессов (P4 раньше P3). RR же через 3 единицы
вытесняет P1 и даёт коротким процессам выполниться сразу: P2, P3, P4 завершаются к
t=4, 6, 7. Цена — P1 и P5 ждут дольше, но в среднем ожидание меньше.
(Вытесняющий SRTF был бы ещё лучше, но он не входит в вариант A.)

Простой CPU с t=19 до t=25 одинаков для всех алгоритмов и на P6 не влияет.

## Выводы

* FCFS прост, но страдает от эффекта конвоя (set2: WT = 17).
* SJF минимизирует среднее ожидание, когда короткие процессы уже в очереди
  (set1, set2), но в невытесняющем виде не спасает, если длинный процесс начал
  работать раньше (set3).
* RR даёт хорошую отзывчивость для коротких задач при смешанной нагрузке (set3),
  но при похожих длительностях проигрывает из-за дробления (set1).
* Результат зависит от соглашений о равенствах и порядке очереди RR, поэтому их
  нужно явно фиксировать.

## Ответы на контрольные вопросы

> Вопросы методички недоступны; ниже — ответы на типовые вопросы по теме.

1. **Время ожидания и время оборота?** TAT — от прихода до завершения; WT — время,
   проведённое в очереди готовых: `WT = TAT − burst`.
2. **Что такое эффект конвоя?** Короткие процессы ждут за длинным в FCFS (set2).
3. **Почему SJF оптимален?** Для невытесняющего случая при одновременно известных
   процессах выполнение коротких первыми минимизирует суммарное ожидание.
   Недостатки: нужно знать burst заранее, возможно голодание длинных процессов.
4. **Как квант влияет на RR?** Очень большой квант превращает RR в FCFS, очень
   маленький — увеличивает число переключений контекста (накладные расходы).
5. **Вытесняющий и невытесняющий алгоритм?** Вытесняющий может отобрать CPU у
   работающего процесса (RR, SRTF); невытесняющий ждёт его завершения (FCFS, SJF).
